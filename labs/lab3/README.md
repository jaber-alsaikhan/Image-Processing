## Running it

The notebook needs `opencv-python`, `numpy`, `matplotlib` and `scikit-image`. They are
already installed in the repository's `.venv`, along with `ipykernel` so the notebook can
run against it.

Open `lab3.ipynb` and select the `.venv` interpreter, then **Run All**. In VS Code the
interpreter is pinned by `.vscode/settings.json`; if it is not picked up, use
`Ctrl+Shift+P` → *Python: Select Interpreter* → `.\.venv\Scripts\python.exe`.

> Running it with a different Python will fail at `import cv2`, because the packages are
> installed in `.venv` and not globally.

## What the notebook does

### Procedural steps

1. **Step#1 — Read an image** with `cv2.imread`. Display goes through matplotlib
   instead of `cv2.imshow`/`cv2.waitKey`, so the notebook runs start to finish without
   opening OS image-viewer windows.
2. **Step#2 — Load an image in grayscale mode** by passing `cv2.IMREAD_GRAYSCALE` to
   `cv2.imread` directly.
3. **Step#3 — Save an image** with `cv2.imwrite`.
4. **Step#4 — Convert to different color spaces** with `cv2.cvtColor`: BGR→gray, and
   BGR→YUV with the Y (luma), U (blue projection) and V (red projection) channels shown
   separately. Also lists how many `COLOR_*` conversion flags the installed OpenCV build
   exposes.

### Task 1 — geometric transformations

| Transform | Implementation |
| --- | --- |
| Increase the size of the image | `cv2.resize(..., fx=2, fy=2)` |
| Rotate by 120 degrees | `cv2.getRotationMatrix2D` + `cv2.warpAffine`, with the output canvas enlarged so the rotated image isn't clipped at the corners |
| Shear | Affine matrix `[[1, shear, 0], [0, 1, 0]]` applied with `cv2.warpAffine`, output canvas widened to fit the sheared result |

### Task 2 — intensity transformations

| Transform | Implementation |
| --- | --- |
| Negative | `s = 255 - r` |
| Log transform | `s = c·log(1 + r)`, with `c` chosen so the brightest input pixel (255) still maps to 255 |
| Power law (gamma) | `s = c·r^γ` with `γ = 0.5`, which brightens shadows and increases contrast; `c` normalized the same way |

The notebook also plots the three input→output intensity mapping curves alongside the
identity line, making the effect of each transform explicit independent of any one image.

## Notes

- Paths resolve from the notebook's own directory, falling back to the working directory
  when `__file__` is undefined — which is the case inside a notebook kernel.
- Rotation and shear both grow the output canvas to fit the transformed image rather than
  cropping it, so no corners are lost off-frame.
